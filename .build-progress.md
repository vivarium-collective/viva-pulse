# viva-pulse build progress

Wrapper for the Kitware Pulse Physiology Engine, bridging the REAL engine
(no PyPI distribution exists; built from source via its CMake superbuild).

## Pins / decisions

- Pulse source: `../engine` (gitlab.kitware.com/physiology/engine), commit
  `5e29e5b13710a08cec90874be7d36ecb192ebcda` (stable + ITM study update).
- Python: uv venv `.venv`, CPython 3.12.12, created with `--seed` (the Pulse
  build runs `python -m pip install protobuf==...` into the selected Python).
- Build dir: `.pulse-build/` (gitignored), install prefix `.pulse-build/install`.
- Toolchain: Apple clang 21, CMake 4.0.3, Unix Makefiles, OpenJDK 17.0.10.

- [x] Phase 2 (respiratory + mechanical ventilator), released as v0.3.0 (PR #4).
  Probes P6/P7 (2026-10-23) each ran in their own subprocess:
  - **Ventilation-mechanics initialization.** `initialize_engine()` segfaults in
    `SubstanceManager::InitializeSubstances` unless
    `SEPatientConfiguration.set_data_root_dir(<install>/bin/)` is set. The data
    root comes from the patient configuration (`Controller.cpp:403`), default
    `./`, not from the engine constructor. Kitware's HowTo assumes the working
    directory is `install/bin`. Initializing from a sex-only patient or from
    `./patients/StandardMale.json` both work; neither needs a mechanics
    configuration (the patient breathes spontaneously: RR 12, TV 448/471 mL).
  - **Requests.** Ventilation-mechanics and whole-body serve the same
    respiratory scalars, gas compartments and ventilator monitor values. NaN on
    both: the leak/needle compartment volumes and the work/power-of-breathing
    scalars. NaN on ventilation-mechanics only (no blood): A-a gradient,
    Horowitz, OI/OSI, S/F ratio and V/Q. Gas compartment pressures are
    absolute (about 1033 cmH2O); `TotalPositiveEndExpiratoryPressure` and
    similar scalars are relative.
  - **Respiratory multipliers, sent incremental** (non-incremental restabilizes,
    and `m_Stabilizer` is null on ventilation-mechanics):
    - compliance x0.5: VM TV 448 -> 255 mL with RR 12 unchanged; WB TV
      508 -> 387 mL with RR 12 -> 15 (chemoreflex compensation);
    - resistance x4: TV barely changes.
  - **Ventilator.** `SEMechanicalVentilatorPressureControl` (AssistedControl,
    PIP 19, PEEP 5, RR 12, Ti 1.0 s, slope 0.2 s, FiO2 0.21) works with or
    without intubation; without intubation it acts as a mask, with Rinsp 22.8.
    Intubated on VM: PIP 13.8, PEEP 5.07, TV 783 mL.
  - **Disconnecting.** A pressure-control action carrying *only*
    `connection=Off` is dropped by Pulse's **Python** API ("Skipping invalid
    action"): `SEMechanicalVentilatorPressureControl.is_valid()` requires FiO2,
    pressures and rate, although C++ `IsValid` accepts a bare Off. A fully
    specified pressure-control action with Off does disconnect, as a mutation
    check showed. We disconnect with `SEMechanicalVentilatorConfiguration`
    whose settings have `connection=Off` (Pulse's scenario idiom); PEEP then
    falls 5 -> ~0. (Correction: an earlier note blamed C++ action removal.)
    Reconnecting with the pressure-control action works on both engines
    (PEEP 5.01 -> 0.0 -> 5.01, PIP 18.9).
  - **AssistedControl auto-triggering (Pulse behavior, not the wrapper).** With
    a set rate of 16 bpm against a spontaneous 12, AC can lock into about
    48-52 bpm with intrinsic PEEP 12-14 cmH2O. Which engine locks depends on
    the breath phase at connect:
    - through the generators: ventilation_mechanics locked (48.4 bpm), whole_body did not;
    - driven directly through Pulse's API (P7 probe, rate 16): whole_body
      locked (RR 51.7, PEEP 13.8), ventilation_mechanics did not.
    Each setting alone (PIP 22, PEEP 7, Ti 1.2) is honoured in AC.
    `ContinuousMandatoryVentilation` honours the full non-default set on both
    engines: PIP 21.98, PEEP 7.2, RR 15.96, I:E 0.47, FiO2 0.4.
  - **Figures by set-up.** The P7 compliance numbers above (VM 448 -> 255,
    WB 508 -> 387) come from a sex-only patient (VM), measured 60 s after the
    modification that followed 30 s of baseline. The generator figures used in
    the tests and README (VM 471 -> 270, WB 510 -> 388) come from the
    `StandardMale.json` patient file, settled, at t = 60 s. Both show the same
    contrast.

## Release fixes

- v0.2.1 (2026-10-23): `requires-python` changed from `>=3.10` to `>=3.11`.
  `bigraph-viz>=2.0.3`, added by the workspace scaffold, needs Python >= 3.11,
  so `uv sync`/`uv lock` could not resolve. That broke the v0.2.0 image build
  (`build-and-push.yml`). Regression test: `tests/test_packaging.py` runs
  `uv lock` on a copy of `pyproject.toml`; verified to fail with `>=3.10`.

## Build workarounds

- `-DPython3_EXECUTABLE` is ignored: Pulse's top-level CMakeLists calls
  `remove_cmake_variables(Python3_)` before `find_package(Python3)`. Use
  `-DPulse_PYTHON_HOME_DIR=<venv>` (forwarded to the Innerbuild) plus
  `VIRTUAL_ENV=<venv>` in the environment. Configure:

  ```bash
  VIRTUAL_ENV=$PWD/.venv cmake --fresh -S ../engine -B .pulse-build \
    -DCMAKE_BUILD_TYPE:STRING=Release -DPulse_PYTHON_HOME_DIR=$PWD/.venv \
    -DPython3_FIND_VIRTUALENV=ONLY \
    -DPulse_JAVA_API=ON -DPulse_PYTHON_API=ON -DPulse_GEN_DATA=ON
  VIRTUAL_ENV=$PWD/.venv cmake --build .pulse-build -j 12
  ```

- process-bigraph 1.10 / bigraph-schema 1.8.2 drop `initial_state()` values on
  `overwrite[float]` and `boolean` output ports (the filled schema default wins
  in `Composite` init's `combine`). Upstream behavior, not patched here.
  Design consequence: vitals are plain `float` ports emitting deltas against
  the previous Pulse reading (seeded by `initial_state()`), and the death flag
  is `irreversible_state` (correct initial value == default False).
  Regression test: `tests/test_composites.py::test_first_emitted_row_carries_loaded_vitals`.
  **Retired 2026-10-26:** process-bigraph 1.10.1 (#268) seeds `overwrite[float]`,
  `boolean` and nested overwrite ports from `initial_state()` (this repro, extended,
  prints 42.0 / True for all), so the outputs are now `overwrite[float]` carrying
  absolute readings. Kept below as history.
  Minimal repro (prints `float {'x': 42.0}`, `overwrite[float] {'x': 0.0}`,
  `maybe[float] {'x': 42.0}`; `boolean` with initial True prints False):

  ```python
  from process_bigraph import Process, Composite, allocate_core
  for typ in ('float', 'overwrite[float]', 'maybe[float]'):
      class P(Process):
          def inputs(self): return {}
          def outputs(self): return {'x': typ}
          def initial_state(self): return {'x': 42.0}
          def update(self, s, i): return {}
      core = allocate_core(); core.register_link('P', P)
      sim = Composite({'state': {'p': {'_type': 'process', 'address': 'local:P',
                                       'outputs': {'x': ['s', 'x']}}}}, core=core)
      print(typ, sim.state['s'])
  ```
- GNU `timeout` is not on macOS; run probes without it (each well under 120 s).
