## Approach: build from source once per pin, cache the install

- **New unstamped workflow `.github/workflows/pulse-engine-ci.yml`.**
  - Triggers: `pull_request`, `push: main`, `workflow_dispatch` with a `force_rebuild` input, and a weekly `schedule` (keeps the cache from being evicted after 7 days).
  - One job on `ubuntu-24.04`, `timeout-minutes: 180`.
- **Toolchain:** Temurin JDK 17, `cmake==4.0.3` through `uv tool`, clang, and `uv python install 3.12.12` then `uv venv --seed`.
- **Cache key:** `pulse-v1-${os}-${arch}-<engine SHA>-py3.12.12-cmake4.0.3-<clang version hash>-<hash of .github/scripts/build-pulse.sh>`.
- **Cold path:**
  1. Clone `REL_4_4_0` with `--depth 1` and assert the SHA.
  2. Install `engine/requirements.txt`.
  3. Run the exact configure and build from `.build-progress.md`, moved into `.github/scripts/build-pulse.sh`.
  4. **Verify before saving the cache:** `bin/PyPulse*.so`, `bin/states/StandardMale@0s.json`, `bin/patients/StandardMale.json` and `python/pulse/**/*_pb2.py` must all exist, so a broken build is never cached.
- **What's cached:** `.pulse-build/install` minus `lib/` and `include/` (PyPulse is statically linked). Locally that is about 286 MB; estimated 80-150 MB compressed.
- **Tests:** set `PULSE_INSTALL_DIR`, then run `pytest tests/ -rA --junitxml`.
- **Template replacement:** delete `workspace-ci.yml` and port its non-test steps: the local-path check, lint, README freshness, workflow freshness and the render check. Note in `CLAUDE.md` that re-scaffolding brings it back. Longer term, propose an opt-in engine-build hook upstream in viva-template.

## Venv without `uv sync`

- **Cold path:** the build pip-installs `protobuf==7.35.0`.
- **Warm path:**
  1. `uv pip install -e ".[dev]"`
  2. the engine `requirements.txt` (at the pinned SHA)
  3. `uv pip install protobuf==7.35.0`, last.
- **Both paths:** assert `google.protobuf.__version__ == "7.35.0"`.
- Do not commit `uv.lock`: it would resolve protobuf to 7.36.x.

## Proof that the engine actually ran

1. **Canary.** A pre-test step, mirrored in a new `tests/test_engine_canary.py`, does four things:
   - asserts `PyPulse.__file__` is under `$PULSE_INSTALL_DIR/bin`;
   - loads StandardMale;
   - advances 10 s;
   - fails on NaN, or on HR outside 72±1.
2. **Skip gate.** Parse the JUnit report and fail on any skip except the allowlisted `test_composite_state_artifacts`, or if fewer tests pass than the local count.
3. **Platform numerics.** Some anchors are absolute values from macOS arm64 (HR 72, MAP 95.3, BV 5487). Record the Linux values from the first run in `.build-progress.md`. Don't loosen tolerances blindly.

## Cost and risk

- **Wall time** (estimates on the 2-vCPU private-repo runners): cold about 1-2 h, warm about 5-8 min. GitHub Free gives 2,000 min/month. No macOS legs (10x billing), or weekly at most.
- **Cold-path rot.** Dependency download URLs (absl, Eigen, protobuf) can disappear, and the cache hides that. A monthly `force_rebuild` catches it.
- **Suspected upstream bug.** `External_protobuf.cmake:88` looks broken: `-force-reinstall` typo, a `protobuf==5.35.0` pin, and possibly an empty `${Python_EXECUTABLE}`. It's a no-op today; watch it.
- **Enforcement.** Required status checks on a private repo need GitHub Pro or Team; the branch-protection API returned 403 on this repo.
- **Docker image.** `build-and-push.yml` (runs on `v*` tags) builds the template Dockerfile: Python 3.13 with no Pulse. That image can serve the workbench dashboard but can't run any Pulse composite. A Pulse-capable image would reuse this cached build and is a follow-up.
